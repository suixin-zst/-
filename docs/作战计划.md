# 「台前」— 主持人 × 商家 直聘式撮合平台 · 黑客松作战计划

> 工作代号：台前（备选：话筒来了、主持直聘）
> 一句话：**BOSS直聘 for 主持人** —— 商家发单、主持人接单、双方直接聊，砍掉微信群和中介抽成。

---

## 1. 痛点（写给评委听的版本）

**主持人侧：**
- 专业主持（含电视台级别）接商单靠微信群 + 熟人介绍，渠道零散、被动等活
- 没有作品沉淀和个人品牌阵地，每次接单都被当"新人"重新介绍
- 议价不透明，被群主 / 中介抽 20%~50%

**商家侧：**
- 找主持人没有正规渠道：要么走中介（贵），要么群里赌运气（踩坑）
- 看不到真实作品和过往评价，选人全凭一张嘴
- 临时放鸽子、临场翻车没有保障机制

**价值主张：** 直接沟通、透明报价、作品说话、平台担保。
中介抽 30% → 我们抽 8%，这就是核心卖点。

---

## 2. 产品定位

- **双边平台**：供给侧（主持人）× 需求侧（商家）
- **核心交互模式**：直接聊天（学 BOSS 直聘的"直"）
- **信任机制**：作品集 + 评价 + 认证标（学淘宝 / 大众点评）
- **签名式 UX**：首页即分流 —— 「我是主持人」/「我是商家」，一进门就进入自己的世界，两套界面、两种语言体系

### 用户画像

| 侧 | 人群 | 动机 |
|---|---|---|
| 主持人 | 电视台/电台在职主持 | 赚外快 |
| 主持人 | 自由职业商业主持 | 主业、稳定单源 |
| 主持人 | 传媒院校学生 | 练手、起步攒作品 |
| 商家 | 活动公司 / 公关公司 | 长期高频需求 |
| 商家 | 中小企业市场部 | 年会、发布会、路演 |
| 商家 | 展会 / 4S店 / 售楼处 | 驻场讲解 |

| 模块 | 主持人端 | 商家端 |


- 电子合同、活动取消保险、主持培训营
- 合规提醒：真实上线需 ICP 备案、经营性 ICP 许可、支付分账资质 —— demo 阶段不碰钱

## 4. 技术方案

### 选型：Next.js 15 + TypeScript + Tailwind CSS + Supabase + Vercel

为什么（针对黑客松）：
1. **一个仓库搞定前后端**，不用配服务器，团队分工简单
2. **Supabase 免费档白送最难的后端**：Postgres + Auth（邮箱/手机号）+ Storage（作品视频）+ Realtime（聊天）
3. **Vercel 每个 PR 自动生成预览链接**，队友互相看进度零成本，评委现场扫码就能玩

### 核心数据表（初版 schema）

```sql
create table users (
  id uuid primary key references auth.users,
  role text check (role in ('host','merchant')),
  name text,
  avatar_url text,
  created_at timestamptz default now()
);

create table host_profiles (
  user_id uuid primary key references users(id),
  city text,
  gender text,
  styles text[],              -- 婚礼/年会/发布会/路演/展会/直播
  bio text,
  price_hourly int,
  price_half_day int,
  price_full_day int,
  experience_years int,
  is_verified boolean default false,
  rating numeric default 0,
  rating_count int default 0
);

create table works (           -- 作品集
  id uuid primary key default gen_random_uuid(),
  host_id uuid references users(id),
  type text,                   -- video/image/audio
  url text,
  title text
);

create table merchant_profiles (
  user_id uuid primary key references users(id),
  company text,
  industry text,
  intro text,
  verified boolean default false
);

create table gigs (            -- 商单
  id uuid primary key default gen_random_uuid(),
  merchant_id uuid references users(id),
  title text,
  type text,                   -- 年会/发布会/路演/展会/婚礼
  city text,
  event_date date,
  duration text,               -- 2小时/半天/全天
  budget_min int,
  budget_max int,
  requirements text,           -- 性别、风格、经验要求
  description text,
  status text default 'open'   -- open / matched / closed
);

create table applications (    -- 报名/邀约统一表
  id uuid primary key default gen_random_uuid(),
  gig_id uuid references gigs(id),
  host_id uuid references users(id),
  initiator text,              -- host(主动报名) / merchant(主动邀约)
  status text default 'pending', -- pending / accepted / rejected
  message text
);

create table conversations (
  id uuid primary key default gen_random_uuid(),
  gig_id uuid references gigs(id),  -- 可空：脱离商单也能直接聊
  host_id uuid,
  merchant_id uuid,
  created_at timestamptz default now()
);

create table messages (
  id uuid primary key default gen_random_uuid(),
  conversation_id uuid references conversations(id),
  sender_id uuid,
  content text,
  created_at timestamptz default now()
);

create table reviews (
  id uuid primary key default gen_random_uuid(),
  gig_id uuid references gigs(id),
  reviewer_id uuid,
  reviewee_id uuid,
  rating int,
  content text,
  created_at timestamptz default now()
);
```

RLS 行级权限：主持人只能改自己的 `host_profiles`，商家只能改自己的 `gigs`，未成交前互相看不到手机号（用平台中转聊天）。

### 页面路由结构

```
/                    首页（角色分流 + 平台介绍）
/auth                注册/登录（选角色）
/host/dashboard      主持人工作台
/host/profile/edit   资料编辑
/host/gigs           商单大厅
/gig/[id]            商单详情（报名）
/merchant/dashboard  商家工作台
/merchant/gig/new    发布商单
/merchant/hosts      主持人列表
/host/[id]           主持人公开主页（作品）
/chat                聊天（会话列表 + 聊天窗）
```

### 关键实现要点

- 聊天：Supabase Realtime 订阅 `messages` 表的 insert 事件
- 作品视频：Storage bucket + 签名 URL，限制大小
- **种子数据是 demo 效果的决定性因素**：写 seed 脚本，准备 8~10 个"像样"的主持人主页（真人感资料 + 作品视频）+ 5~6 张真实感商单

## 6. GitHub 协作 SOP（详细步骤）

### 第一步：建仓（队长，15 分钟）

1. GitHub 新建仓库 `taiqian`（public，勾选 Add README）
2. Settings → Collaborators → 邀请全部队友
3. 一次性放好四个文件：
   - `README.md`：项目一句话、技术栈、本地启动步骤
   - `.gitignore`：`node_modules/`、`.next/`、`.env*`
   - `.env.example`：列出所有环境变量名（不含值）
   - `.github/PULL_REQUEST_TEMPLATE.md`：做了什么 / 怎么测 / 截图
4. 建一个 GitHub Projects 看板，四列：`Todo / In Progress / Review / Done`

### 第二步：初始化项目（全栈同学）

```bash
git clone https://github.com/<你的用户名>/taiqian
cd taiqian
npx create-next-app@latest . --typescript --tailwind --app
git add . && git commit -m "chore: next.js 脚手架"
git push
```

Supabase 官网建项目 → 拿 `SUPABASE_URL` 和 `ANON_KEY` → 填进本地 `.env.local`（不进 git）→ 群里私下同步给队友。

### 第三步：把 P0 功能拆成 Issue

- 每个功能一个 Issue：标题 + 验收标准 + 指派负责人
- 例：「feat: 商单列表页 + 筛选（负责人 A）」验收标准：能按城市/预算筛选，空态有占位图
- 所有 Issue 进看板 Todo 列，开工拖到 In Progress

### 第四步：日常开发循环（每个人）

```bash
# 开工：同步最新代码
git checkout main && git pull origin main

# 开新分支（一人一个功能分支，禁止直接推 main）
git checkout -b feat/gig-list

# 小步提交
git add . && git commit -m "feat: 商单卡片组件"

# 完成：推送并开 PR
git push -u origin feat/gig-list
```

GitHub 上开 Pull Request → 填模板 → 看板拖到 Review → 队友 Approve → **Squash merge** → 删分支。

### 分支与提交规范

- 分支：`feat/xxx`、`fix/xxx`、`docs/xxx`、`chore/xxx`
- commit：动词开头说清改了什么，如 `feat: 商单列表筛选`
- main 保护：Settings → Branches → 给 main 加规则 "Require pull request before merging"（黑客松阶段不强制 review 人数，1 人点过就行）

### 冲突预防（比解决更重要）

- 每天开工先 `git pull`，下班前 push（没写完就 `wip` commit）
- **约定文件归属**：A 只动 `/host` 相关页面和组件，B 只动 `/merchant` —— 从物理上消灭 80% 冲突
- 真冲突了：`git fetch && git rebase origin/main`，同文件冲突找当事人一起看，别自己硬猜

### Vercel 部署

1. vercel.com → Import GitHub 仓库 → 自动识别 Next.js
2. Environment Variables 里贴 Supabase 的 key → Deploy
3. 之后：push 到 main 自动更新正式链接；**每个 PR 自动生成预览链接**（在 PR 页面底部）
4. demo 当天用 main 的线上链接，别用 localhost

## 8. Demo 脚本（3 分钟）

1. **开场 30s**：讲痛点（放一张微信群里接单混乱的截图/故事）
2. **90s 现场跑核心闭环**：商家发一张「新车发布会主持」商单 → 切主持人账号，浏览、报名 → 切回商家，看资料作品、发消息 → 主持人回复，达成合作
3. **30s**：商业模式一页（抽佣 8% vs 中介 30%）
4. **30s**：愿景（从撮合到行业标准：认证、担保、保险）

### 评委 Q&A 预案

- **冷启动怎么办？** 先打供给侧：地推主持社团 / 传媒院校，主持人免费入驻攒作品；商家端先做活动公司（高频刚需）
- **凭什么不是猪八戒 / BOSS直聘的子集？** 垂直行业的作品形态（视频 demo）、档期系统、主持行业定价结构（时/半/全天）是通用平台做不深的
- **怎么赚钱？** 成交抽佣 + 双端会员增值，长期加保险和培训
